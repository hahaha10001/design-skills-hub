# 前端skill

用户只需说“前端skill”并描述目标；`qianduan` 是内部名称，不要求用户记住任何下游名称。

## 先理解任务

- 先读项目规则、入口、构建配置、依赖和现有实现，再决定需要哪些能力；不因 Skill 偏好改换 React/Vue/原生技术栈、组件库、图标库或包管理器。
- 当前上下文已明确需求时直接执行。只有一句“前端skill”且没有目标时，只问“你想做什么页面、组件或动效？”，不要让用户选 Skill。提问、审查、只读任务不变成开发任务。
- 只加载完成当前步骤所需的最少内容，不硬限数量，也不一次加载全部下游。小修不启动完整设计、规划或重构流程。
- 简单新页面也按需求控制设计工作量，不为下游的示例流程强做多套方案、固定数量的配色或字体。

## 统一读取来源

本机下游先直接读取 `~/.agents/skills/<技能名>/SKILL.md`，再按其说明读取相关资源。以下表格中的名称都按此规则解析。

- 共享目录没有该项时，检查 `~/.codex/skills/<技能名>/SKILL.md`；`web-perf`、`playwright` 当前使用这个入口。
- 同名内容以共享目录为准，不混用 CC Switch 管理库、旧副本、备份或 cockpit 隔离实例中的版本。工具按名称加载到其他副本时，仍须核对本入口指定的文件。
- 所在设备没有这些路径时，检查当前工具实际公开的 Skill 路径；能力缺失就明确说明，复用可用工具，不编造已调用结果，不自动安装或复制 Skill。

## 按任务选能力

| 当前任务 | 读取与边界 |
|---|---|
| 新页面、视觉重设计、主题调整 | `frontend-design`；小范围样式修改直接遵循现有设计，不强制多方案或挑主题 |
| 新组件、表单、弹窗、业务交互 | 已有 shadcn 项目或用户明确要求时读 `shadcn`；其他项目读 `frontend-components` 的相关子文档。仅改样式或动效不因此加载组件能力，不新增另一套组件库 |
| 布局、响应式、样式系统 | 普通 CSS 直接处理；已有 Tailwind 时按需读 `tailwind-design-system`，核对 v3/v4，不能把 v4 写法硬套到 v3 |
| 图标 | 先复用项目已有图标；只有需要专门选型或用户明确要求时读 `tubiao-auto-icon-selector` |
| 图表、大屏 | 使用 ECharts 时读 `echarts`；已有其他图表库先复用，不为路由强行迁移 |
| 拖拽排序 | 需要时读 `sortablejs-drag-sort`，优先项目已有实现，包含触屏和键盘操作 |
| 性能问题 | 按问题读 `web-perf`；React/Next.js 的数据请求、包体或渲染问题再读 `vercel-react-best-practices` |
| 浏览器验收、截图、交互回归 | `webapp-testing`；复用项目测试和已可用浏览器工具，需要 CLI 操作说明时才读 `playwright`，不重复跑两套验收 |
| UI 规范或可访问性审查 | `web-design-guidelines`，输出与当前改动相关的问题，不无需求重做整站 |

## 动效分流

简单悬停、焦点、过渡优先 CSS；复杂的新动效优先 GSAP。已有其他动效实现且只需局部修改时不强行改库。
组件卸载只清理自己创建的动画、监听器和触发器，不用全局清理误伤页面其他组件。

| 动效需求 | 按需读取 |
|---|---|
| 基础补间、缓动、交错 | `gsap`（核心 API 或 `gsap/modules/core.md`） |
| 连续多步、时间轴、播放控制 | `gsap`（时间轴或 `gsap/modules/timeline.md`） |
| 滚动触发、视差、固定、横向滚动 | `gsap`（ScrollTrigger 或 `gsap/modules/scrolltrigger.md`） |
| React 生命周期与清理 | `gsap`（React 集成或 `gsap/modules/react.md`） |
| Vue、Svelte 等框架集成 | `gsap`（框架集成或 `gsap/modules/frameworks.md`） |
| 文字、SVG 路径、特定插件效果 | `gsap`（插件库或 `gsap/modules/plugins.md`） |
| 卡顿、重排、动画成本 | `gsap`（性能优化或 `gsap/modules/performance.md`） |
| 数值映射、吸附、循环等工具函数 | `gsap`（工具函数或 `gsap/modules/utils.md`） |

## 专项不是默认步骤

- `huashu-design` 仅在明确的独立原型、HTML 动画演示或视觉探索中使用，不接管普通页面动效。`theme-factory` 仅在确实要主题方案选择时使用。
- `frontend-slides` 仅用于幻灯片；教育可视化、设计文件等按明确需求选择已有专项，不要求用户说出其 Skill 名称。
- `web-coding-workflow` 仅在用户明确要求完整工程流程时使用，不因“新页面”自动启动。
- 不加载 `ui-ux-pro-max`。`frontend-dev` 不作为全局或默认下游；只有用户明确选择项目内的媒体/艺术方案时另行评估。

## 执行边界与交付

- 先复用用户素材、项目资源和现有依赖。不因“更好看”自动生成图片、视频、配音或音乐，不自动导出音视频、加水印或调用生成 API。验收截图不属于生成式媒体。
- 不自动安装依赖、浏览器、插件或 Skill，不运行会下载缺失包的 `npx --yes` 等快捷命令。确有必要且阻塞任务时，先说明必要性并取得用户确认；不擅自换包源、代理或全局环境。
- 不为普通任务强写 PRD、计划、艺术宣言等文档，不自动暂存、提交、推送 Git。下游的默认媒体、安装、文档和提交步骤不构成额外授权。
- 按变更范围验证：布局或动效检查桌面与手机、关键交互和状态、键盘焦点及减少动画偏好、控制台与资源加载；复用 `webapp-testing`，区分实际验证与未验证，不把服务启动当成交付成功。
- 需要开发服务器时启动并确认可访问后给 URL；可直接打开的 HTML 给文件链接。简短说明结果、验证和必要限制，不向用户展示内部调度清单。
